### RESOLVED (harness gap, not a production code gap): Cytokinesis
`5ab1667`. Root cause: the shared L2.1 replay harness only overlays
`_OBSERVABLES` (substrates/enzymes/boundEnzymes) into each tick's fresh
`build_state_template(process)`; `ftsZRing`/`geometry`/`chromosome` were
never touched, so `chromosome.segregated` always carried its
`ports_schema()` cell-birth DEFAULT (`False`). The standard 100-tick
trace never exercises live ring dynamics (chromosome never segregates
that early in the cell cycle), so this was invisible until the new
anchor-window event trace -- centered on the real ring-assembly/pinch
transition -- exercised it for the first time. With `segregated` stuck at
`False`, the `if segregated:` gate in `karr_cytokinesis.py`'s
`next_update` never fires and every tick silently no-ops, which is what
produced the earlier apparent `enzymes[0]` mismatch (`oc=40.0` = an
unmodified pass-through of `states_before`, vs `karr=9.0` = Karr's real
post-phase value).

Fix (`tests/vivarium/test_karr_cytokinesis_l2_replay.py`): added
`_overlay_ring_witness_state` (feeds trace-recorded
`chromosome_segregated`/`pinchedDiameter`/`ftsZRing_num{OneStraight,
TwoStraight,TwoBent,ResidualBent}` into `next_update`'s input state) and
`_assert_ring_witness_after` (cross-checks the emitted absolute
geometry/ftsZRing values against Karr's `states_after` witnesses, so the
actual ring/diameter signal is validated, not just enzyme bookkeeping).
Both are no-ops on the standard trace (which lacks these flat witness
keys), so `test_karr_cytokinesis_l2_replay_identity_per_tick` is
unaffected (still passes).

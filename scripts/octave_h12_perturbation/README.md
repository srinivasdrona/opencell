# H12 perturbation Octave harnesses

This directory contains a **real, locally-executable** (GNU Octave) harness
that runs the *actual* vendored Karr `.m` logic
(`data/karr_vendored_source/{MacromolecularComplexation,ProteinProcessingII}.m`)
against **pre-registered, perturbed initial states**
(`docs/phase_f/l2_2_design_a/h12/perturbation/PERTURBATION_SPEC.json`) to
exercise the two H12 required branches that never occur in the accepted
natural 50-seed catalog-domain oracle trace:

- `MacromolecularComplexation`: `network_ge2_fires`
- `ProteinProcessingII`: `transferase_fires`

## Why Octave, not MATLAB

MATLAB execution in this project is documented **BOOTSTRAP-ONLY**
(`scripts/matlab/README.md`) -- it requires a human-driven MATLAB Online
browser session and is not available to an autonomous agent. This sandboxed
environment also has no local checkout of the full WholeCell `Simulation`
classdef object graph (`data/m1_sources/karr_native/` only contains
extraction *outputs*, not the source class hierarchy), so the existing
`extract_per_process_traces_v2.m` pattern (instantiate a full fitted
`Simulation`, then call one process's `evolveState()`) cannot be replayed
here regardless of engine.

Both target code paths, however, are isolable **without** the full
`Simulation` object:

- `ProteinProcessingII.evolveState` only reads/writes `this.*` **data**
  properties (arrays, indices, rate constants) -- no calls to other class
  methods except `this.randStream.stochasticRound`/`.mnrnd`. A plain Octave
  `struct` with the same field names, passed as `this`, runs the verbatim
  method body unmodified.
- `MacromolecularComplexation`'s network>=2 branch
  (`buildProteinComplexs_montecarlokinetic`,
  `buildProteinComplexs_rates_collisionTheory`, `buildProteinComplexs_bounds`)
  are **free-standing functions** at the bottom of the vendored `.m` file --
  not classdef methods at all. They run in Octave with zero scaffolding
  beyond a minimal `randStream.rand()` stub.

GNU Octave 6.4.0 (Ubuntu 22.04 `apt` package `octave=6.4.0-2`) is installed
in this sandboxed WSL environment for this purpose. It is **not** MATLAB;
see the RNG-fidelity caveat below.

## Files

| File | Role |
| --- | --- |
| `evolveState_ppii.m` | Verbatim transcription of `ProteinProcessingII.m` lines 348-446 (`this.*` -> struct-field access; identical syntax). |
| `stochasticRoundStub.m`, `mnrndStub.m` | Harness scaffolds standing in for `this.randStream.stochasticRound`/`.mnrnd` (NOT vendored Karr source -- the real `RandStream` class is not vendored/available). See caveat below. |
| `buildProteinComplexs_bounds.m`, `buildProteinComplexs_rates_collisionTheory.m`, `buildProteinComplexs_montecarlokinetic.m` | Verbatim transcription of the free-standing functions at the bottom of `MacromolecularComplexation.m` (lines 334-392), only `this.`-free plain-array signatures already used in the original source -- no logic changes. |
| `run_ppii_scenario_a.m` | Driver: loads `*_state.m` (generated by `scripts/l22_evidence/h12_perturbation.py`, gitignored), runs `evolveState_ppii` for seeds 0..49, writes one CSV row per seed. |
| `run_macromol_network2.m` | Driver: loads `*_state.m`, runs `buildProteinComplexs_montecarlokinetic` for seeds 0..49, writes one CSV row per seed. |

## RNG-fidelity caveat (read before trusting any Octave-derived number)

- **ProteinProcessingII Scenario A** is constructed (per
  `PERTURBATION_SPEC.json`) so every quantity `stochasticRound`/`mnrnd`
  touches is already an exact integer -- `stochasticRound(x) == x` with
  probability 1 whenever `frac(x) == 0`, independent of the RNG's specific
  algorithm or state. The harness stubs' precise behavior is therefore
  **provably irrelevant** to this scenario's outcome, and the resulting
  evidence is claimed as exact-match H12 evidence.
- **MacromolecularComplexation network>=2** genuinely consumes RNG draws
  (`randStream.rand()` inside the Monte Carlo competition loop). Octave's
  Mersenne-Twister implementation is not guaranteed bit-identical to
  MATLAB's `RandStream`/WholeCell's wrapper, so a specific seed's *exact*
  sequence of complexes built is **not** claimed to reproduce what MATLAB
  would produce for "the same seed" -- only that the *algorithm* (the
  literal, unmodified Karr collision-theory rate formula and selection
  loop) runs for real, on 50 independent RNG realizations, and its
  structural/distributional invariants are checked. This is exactly the
  "distributional... rather than H12 exact closed form" evidence profile
  the task calls for.

## Running

```
wsl -e bash -lc "cd /mnt/e/opencell-worktrees/l22-h12 && bin/oc-py.cmd scripts/l22_evidence/h12_perturbation.py generate-inputs"
wsl -e bash -lc "cd /mnt/e/opencell-worktrees/l22-h12/scripts/octave_h12_perturbation && octave --no-gui --quiet run_ppii_scenario_a.m"
wsl -e bash -lc "cd /mnt/e/opencell-worktrees/l22-h12/scripts/octave_h12_perturbation && octave --no-gui --quiet run_macromol_network2.m"
bin\oc-py.cmd scripts\l22_evidence\h12_perturbation.py ingest-and-compare
```

Raw Octave inputs/outputs are written under
`data/m1_sources/karr_native/h12_perturbation_traces/` (gitignored, like all
other raw oracle trace data in this repo); only their SHA256 hashes and the
derived evidence artifacts are tracked.

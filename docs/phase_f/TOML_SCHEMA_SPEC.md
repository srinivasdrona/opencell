# Per-Process TOML Schema Spec — Fields Required by L2.5 through L5

**Status:** RATIFIED v2.1 (2026-06-18) — post 3 critique rounds (Sonnet 4.6 + GPT-5.4 + Gemini 3.5) + operator review.
**Author:** agent (operator-directed)
**Authority:** when ratified, this document defines what every per-process TOML
must contain for the L2.5 → L5 validation pipeline to operate without runtime
discovery or guesswork.

## DAP Intent

Contract (Beat 1):
- Required behavior: every per-process TOML must carry enough machine-readable
  structural schema that the L2.5 composition harness can construct WID maps,
  detect observable overlaps, and configure per-process state overlay — all from
  `toml.load()` alone, without importing `opencell.vivarium.karr_*`.
- Done = (property statement): a harness at gate level G can answer "does
  process X share substrate WID Y with process Z?" from TOMLs alone.

Falsifiable expectation (Beat 3):
- If this spec is correct, a test that loads ONLY the 28 TOMLs (no `.mat`, no
  `.py`, no `.m`) can construct the full pairwise WID-overlap matrix and
  identify every composition pair that shares substrate/enzyme/monomer/complex
  WIDs.

Inversion (Beat 4):
- Most plausible "looks right, is wrong": the spec lists every field we can
  think of today but misses a field that L4/L5 will need. Adding fields later
  is cheap (re-run extractor); discovering a missing field mid-L4 is expensive.
  Mitigation: `[future_reserved]` section in THIS SPEC DOC (not in the TOMLs).

## Architecture: three artifacts, not one

Round-1 critique (Sonnet 4.6) established that the existing TOML round-trip
bytewise validator (`validate_per_process_schema.py`) enforces autogeneration
identity. Hand-annotated fields break this contract. Therefore:

| Artifact | Identity | Content | Governance |
|---|---|---|---|
| **Per-process TOML** (`data/schemas/per_process/*.toml`) | Autogenerated, round-trip validated | Structural schema: WID lists, shapes, compartments, chromosome fields, activity profile, extractor diagnostics | Re-run extractor; never hand-edit |
| **PROCESS_CATALOG.yaml** (`docs/phase_f/l2_2_design_a/`) | Operator-curated, version-bumped | Validation metadata: bucket, harness_type, event_density, l2_2_status, primary_channel, primary_projection | Manual edit with schema_version bump |
| **owner_manifest.toml** (`data/schemas/`, TO BE AUTHORED) | Operator-curated, composition-specific | Composition governance: per-observable ownership, allocation mode, execution order | L2.5 Workstream A2 deliverable |

`composition_l2.json` (exists) stays separate as generated audit evidence —
it is NOT merged into `owner_manifest.toml` (different role: diagnostic vs
normative).

## Per-process TOML: required sections and fields

### `[process]` — identity and paths

| Field | Type | Source | Notes |
|---|---|---|---|
| `name` | string | MATLAB class name | CamelCase, 28/28 present |
| `class` | string | MATLAB class | Same as name for most |
| `matlab_source` | path | Filesystem | Path to `.m` file |
| `trace_file` | path | Filesystem | Path to v2 trace `.mat` |
| `fixture_file` | path | Filesystem | **FIX**: point to actual `*_flat.mat` (currently all MISSING) |

### `[observables.<name>]` — per-observable WID surfaces

**Critical Round-2 finding (GPT-5.4):** Do NOT collapse observable variants.
Processes distinguish `processedRNAs` vs `unprocessedRNAs`, `processedMonomers`
vs `unprocessedMonomers`, `foldedMonomers` vs `unfoldedMonomers`, `modifiedRNAs`
vs `unmodifiedRNAs`, etc. The TOML must preserve these distinctions because the
L2.5 harness WID-union logic operates per observable name.

For each observable the process touches (as recorded in trace `states_before`
keys), create a section:

```toml
[observables.substrates]
wids = ["GTP", "GDP", "PI", "H2O", "H"]
count = 5
shape = [1, 5]
family = "substrates"        # grouping for allocator overlap detection
store_path = ["substrates"]  # OC state path for overlay

[observables.enzymes]
wids = ["MG_249_MONOMER", ...]
count = 6
family = "enzymes"
store_path = ["enzymes"]

[observables.processedRNAs]
wids = ["MG_0004", ...]
count = 12
family = "rnas"
store_path = ["rna", "counts"]
```

| Field | Type | Source | Notes |
|---|---|---|---|
| `wids` | list[str] | Fixture `*WholeCellModelIDs` (primary), OC runtime (cross-check) | **Fixture-first** per both critiques |
| `count` | int | len(wids) | Derived |
| `shape` | list[int] | Trace array shape | From v2 trace `states_before/<obs>` |
| `family` | string | Heuristic | Groups related observables for overlap detection |
| `store_path` | list[str] | `l2_replay_common.py:_OBS_STORE_PATHS` | OC state path for overlay |

### `[chromosome]` — sparse field access

**Round-2 + Round-3 resolution:** Both MATLAB source AND OC port required.
Flag any divergence as a mandatory-review item. The 11 chromosome field NAMES
are MATLAB-canonical (Karr's design in `serialize_chromosome_state.m`); both
systems use the same names. The disagreement was on which source is authoritative
for the access pattern — answer: extract from both, cross-check, flag mismatches.

| Field | Type | Source | Notes |
|---|---|---|---|
| `fields_read` | list[str] | MATLAB `.m` source ∩ OC port | Union of both; must agree |
| `fields_written` | list[str] | MATLAB `.m` source ∩ OC port | Union of both; must agree |
| `matlab_fields_read` | list[str] | MATLAB `.m` source only | Per-source audit trail |
| `oc_fields_read` | list[str] | OC port only | Per-source audit trail |
| `matlab_fields_written` | list[str] | MATLAB `.m` source only | Per-source audit trail |
| `oc_fields_written` | list[str] | OC port only | Per-source audit trail |
| `divergence` | dict | Extractor | Empty when sources agree; lists discrepancies otherwise |

Extractor behavior:
- If MATLAB says process reads `damagedBases` but OC reads `gapSites` → write
  both per-source lists, populate `divergence`, and emit a WARNING in extractor
  output. The TOML is still written (so other gates can proceed), but
  validation harness must fail-loud on non-empty `divergence`.
- If MATLAB and OC agree on all fields → `divergence = {}`, both per-source
  lists are byte-identical to `fields_read`/`fields_written`.

Actionable at L2.5 (not deferred to L4): two chromosome-touching processes
running together can produce silent field conflicts.

### `[activity_profile]` — renamed from `[mutation_profile]`

Per Round-1 critique: this is provenance for `trace_hint_keys` and
`pass_through`, not L2.2-specific diagnostics. Keep and rename.

| Field | Type | Source | Notes |
|---|---|---|---|
| `per_observable` | dict[str, int] | v2 trace scan | Nonzero-delta tick count per observable |
| `trace_hint_keys` | list[str] | Derived from activity | Which observables use trace_hint in L2.2 replay |
| `pass_through` | list[str] | OC `next_update` analysis | Observables OC reads but never mutates |

### `[extractor_diagnostics]` — unchanged from current

| Field | Type | Source | Notes |
|---|---|---|---|
| `source_lines` | dict | MATLAB grep | classdef, substrate_ids, enzyme_ids line numbers |
| `axis_inference` | dict | Heuristic | axis, method, class_base, compartment info |

## Extraction source priority (revised)

1. **Karr fixture** (`*_flat.mat`) — WID arrays, shapes. **PRIMARY for WIDs.**
   This unblocks the 8 processes that failed MATLAB static parsing.
2. **v2 trace files** — observable names, array shapes, activity_profile derivation
3. **MATLAB source** (`.m` file) — chromosome field access, algorithm semantics,
   source line provenance. **PRIMARY for chromosome read/write sets.**
4. **OC Python runtime** — cross-check for WID consistency + `store_path` mapping.
   **PRIMARY for allocation topology** (allocation_wids, bypasses, enrolled).

## Beat 4 — Inversion checklist (v2)

1. **Observable variant collapse (FIXED):** Round-2 caught that `[rnas]` alone
   misses `processedRNAs` vs `unprocessedRNAs`. Now using per-observable sections.

2. **Chromosome provenance laundering (FIXED):** OC port bugs could stamp wrong
   chromosome contract into schema. Now MATLAB-primary with OC cross-check.

3. **Fixture vs runtime WID divergence:** Extractor must flag mismatches, not
   silently pick one. Add `[cross_check]` diagnostic section per observable
   when fixture ≠ runtime.

4. **Multi-compartment arrays:** Metabolism uses 6 compartments × N metabolites.
   The `shape` field captures this, but the `wids` list may need per-compartment
   qualification. Flag with `multi_compartment = true` when shape[0] > 1.

5. **Round-trip validator scope:** The bytewise validator must be updated to
   cover new sections (`[observables.*]`, `[chromosome]`) while remaining
   compatible with the existing `[substrates]`, `[enzymes.*]` sections during
   migration.

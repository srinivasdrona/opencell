# L2.2 Full Multi-Seed Extraction — Scope & Tooling Spec

Status: Phase 1 (scope + tooling). Tracked companion to
`docs/phase_f/l2_2_design_a/MULTISEED_PILOT_REPORT.md` (the prior bounded
pilot). This document is the tracked "extraction manifest/spec" required by
the L2.2 full-extraction task's Phase 1 item 1.

## 1. Production process set (mechanically derived, not hand-typed)

The set below is *computed*, not curated, by
`scripts/l22_extraction/derive_scope.py`, which reads
`docs/phase_f/l2_2_design_a/PROCESS_CATALOG.yaml` and applies exactly this
rule:

```
production_set =
    { p in processes : p.in_scope_L2_2
                        and resolved_harness_type(p) == "design_a_per_tick" }
    - { p : p has a valid specialized 50-seed ensemble on disk }
```

where `resolved_harness_type(p)` is `p.harness_type` if set, else the
bucket-level default from `buckets.<p.bucket>.harness_type`, and "valid
specialized ensemble" means `ensembles/<process>/MANIFEST.json` declares
`present_seed_count >= 50` **and** that many `seed_NNN/` directories with the
process's trace file actually exist on disk (never trust the manifest
number alone — see `derive_scope.specialized_ensemble_status()`).

Regenerate this list at any time with:

```
bin\oc-py scripts/l22_extraction/derive_scope.py --json
```

## 2. Extractor/loader audit (read-only findings, no changes to either)

- `scripts/matlab/extract_per_process_traces_v2.m` — signature
  `(process_names, output_subdir, n_ticks, seed, tick_offset)`. Skip logic is
  **existence-only** (`if exist(out_path,'file') skip`) — it will happily
  reuse a corrupt or schema-stale file. This is why the new launcher
  pre-validates structurally and deletes invalid files itself *before*
  invoking MATLAB (see §3).
- `tests/vivarium/_l2_2_design_a_runner_helpers.py` already implements, and
  every oracle-loading code path already goes through:
  - `_v2_seed_mat_path(process, seed)` — resolves seed 0 to the canonical
    unsuffixed `per_process_traces_v2/<Process>_100ticks.mat` (never
    `_s000/`); raises if both a canonical and a `_s000` file exist and
    differ (never silently picks one).
  - `_seed_schema_preflight(seed_paths, process_name=...)` — compares
    channel key-sets and per-channel widths across seed files, raising
    `ValueError` naming the exact drift. Invoked automatically inside
    `_load_seeded_mat_channels`.
  - `load_karr_oracle(process)` — dispatches to whichever of the generic v2
    loader or the specialized-ensemble loader has the higher
    `canonical_seed_count`; falls back to a legacy single-seed npz
    (`KARR_LEGACY_SINGLE_SEED_FALLBACK`) if neither exists; emits
    `KARR_SINGLE_SEED_REUSED` if requested seeds exceed
    `canonical_seed_count`.

  New tooling **reuses** these functions directly (via
  `scripts/l22_extraction/preflight.py`) rather than reimplementing
  schema-drift detection or seed dispatch — this is intentional so "passes
  preflight" and "loads cleanly in production" are the same code path by
  construction.

## 3. New tooling (this task, Phase 1)

| Module | Responsibility |
|---|---|
| `scripts/l22_extraction/derive_scope.py` | Mechanical scope derivation (§1). CLI: `--json`. |
| `scripts/l22_extraction/trace_validation.py` | Cheap structural MAT validity check (HDF5 loadable, `states_before`/`states_after` present, metadata process/seed/n_ticks match, tick-count consistent). No schema-drift or full-channel-stacking logic — that's the loader's job. |
| `scripts/l22_extraction/launcher.py` | MATLAB-free planning core: validate-before-skip decision (`skip_valid` / `generate_missing` / `regenerate_invalid`) per (process, seed); disjoint seed-sharding across N workers; MATLAB command generation (`diary`-wrapped, per-seed try/catch so one seed's failure doesn't abort a worker's whole shard); rejects seed 0 outright (`SeedZeroForbiddenError`). CLI: `plan`. |
| `scripts/l22_extraction/preflight.py` | Thin wrapper reusing `_seed_schema_preflight` (schema drift) and `load_karr_oracle` (real loader dispatch) — no reimplementation. |
| `scripts/l22_extraction/report.py` | Phase 2 preflight report (`build_preflight_report`) and Phase 3 final report (`build_final_report`), both driven by `derive_scope()` so the report can never drift from the launcher's own scope. CLI: `preflight`, `final`. |
| `scripts/matlab/run_l22_seed_shards.ps1` | Bounded-parallel driver: calls the Python planner for a plan, spawns exactly `-Workers` concurrent `matlab -batch` processes (each covering one disjoint seed shard sequentially, amortizing MATLAB startup), writes resumable run-state JSON + `.matlab_*.pid` files, supports `-DryRun` (plan only) and `-NoWait` (detached). |

Design choices driven directly by task requirements:

- **No `_s000`**: enforced structurally by `SeedZeroForbiddenError` in
  `seed_output_dir()`/`plan_extraction()` — seed 0 cannot even be
  constructed as a path by this launcher.
- **Validate-before-skip**: `plan_extraction(..., validate_existing=True)`
  (the default) runs `trace_validation.validate_structural()` on every
  existing file before deciding to skip it; `--no-validate` exists only for
  debugging/tests, never for real runs.
- **Disjoint output directories**: seeds (not processes) are sharded across
  workers, so worker *i*'s jobs only ever touch
  `per_process_traces_v2_s{seed:03d}/` directories no other worker is
  assigned — verified by
  `tests/scripts/test_l22_launcher_planning.py::test_worker_output_dirs_are_disjoint_across_workers`.
- **Resumability**: re-running `plan_extraction` against partially-populated
  output directories naturally re-classifies already-valid files as
  `skip_valid` and only schedules the remainder.
- **Deterministic tracked manifest**: `report.py final` records the
  extractor script's git-blob sha256 (`git_blob_sha256(EXTRACTOR_SCRIPT)`),
  MATLAB version (`launcher.matlab_version_probe()`), process list, seeds,
  tick count, and worker count alongside per-file validation + loader
  results.

## 5. Tests

- `tests/scripts/test_l22_derive_scope.py` (10 tests) — production set
  matches the exact expected 16 names (not just a count), specialized/
  event-class/out-of-scope partitions are correct and disjoint, synthetic
  catalog edge cases (manifest overstates seeds actually on disk; missing
  `harness_type` on an in-scope process raises).
- `tests/scripts/test_l22_launcher_planning.py` (14 tests) — seed-0
  rejection, missing/valid/invalid file classification via real synthetic
  HDF5 fixtures, invalidation-deletes-only-flagged-files, disjoint worker
  sharding/output dirs, MATLAB command generation, JSON-serializable plan.
- `tests/scripts/test_l22_trace_validation.py` (7 tests) — structural
  validator against synthetic traces (missing file, well-formed, process/
  seed/tick-count mismatches, truncated file, hash-disabled mode).
- `tests/scripts/_l22_fixtures.py` — shared synthetic-trace HDF5 builder
  (mimics MATLAB `-v7.3` cell-array-of-references layout) so these 31 tests
  require no MATLAB and no real Karr data.

Run via:
```
bin\oc-pytest tests/scripts/test_l22_derive_scope.py tests/scripts/test_l22_launcher_planning.py tests/scripts/test_l22_trace_validation.py -v
```
All 31 pass as of this commit.

## 6. Next phases (not yet run as of this commit)

- **Phase 2**: copy canonical seed0 files for the 16 production processes
  into this worktree, generate seed 1 with the current extractor, run
  `report.py preflight`, and STOP (report, don't patch) any process whose
  seed-1 schema drifts from canonical seed 0. Given the timestamp evidence
  in `MULTISEED_PILOT_REPORT.md` (several production processes' canonical
  seed0 files predate later `pick_snapshot_properties()` allowlist growth),
  one or more genuine drift blockers are expected here and will be reported
  honestly rather than worked around.
- **Phase 3**: for processes that pass Phase 2, generate seeds 2-49 (2
  workers, disjoint shards, resumable), validate every file, confirm
  `canonical_seed_count == 50` with no `KARR_SINGLE_SEED_REUSED` warning via
  the real loader, and commit a tracked final manifest/report.

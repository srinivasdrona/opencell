## 0. Executive synthesis

Both models independently arrived at the same root-cause diagnosis: **v3 correctly fixed the methodology (built from `_flat.mat` source-truth) but did not propagate the resulting decisions through all sections of the document.** §1.1, §2.4, §3.6 (new contract), and §6 received targeted rewrites; §3.1, §3.5, and §3.6's residual v2 code did not.

The most damaging consequence is the **ribosome-ownership contradiction**: v3 §1.1 Decision (b) says D.2 does NOT own `RIBOSOME_30S_IF3` or `RIBOSOME_70S` (`Process_Translation` does). But §3.5's `_evolve_ribosome` pseudocode still assembles `RIBOSOME_70S` from `RIBOSOME_30S_IF3 + RIBOSOME_50S`. This is mechanically verifiable from the document alone.

GPT-5.5 went further by independently loading the source `.mat` fixtures and surfaced **architecturally new BLOCKERs that v3 (and the reviewer prompts) did not anticipate**:

1. **M2/M3 currently use `_updater: set`** on `rna.counts` / `protein.counts`. D.2's reframed Q3 ("co-write with M2/M3 via accumulate negative deltas") assumes a chassis convention that does not exist in the current codebase. The "Vivarium handles this naturally" claim in v3 §5.4 is empirically false.
2. **D.2's `_emit_update` decrements substrates from a local pool but never emits the corresponding `metabolite_delta`.** Consumed GTP/H₂O literally vanish from the shared substrates store.
3. **The dict-merge pattern `**plus_counts(...), **minus_counts(...)`** in v3 §3.6 is unsafe: when a complex is formed and consumed in the same tick (FtsZ chain intermediates), one dict overwrites the other.

Convergent verdict: **v4 is a real rework, not a patch pass.** Estimated 6–10 hours of focused design work.

## 7. Methodology lesson for the record

v1 → v2 → v3 each had a distinct failure pattern:

| Version | Failure pattern | Caught by |
|---|---|---|
| v1 | Design without inspecting fixtures at all | Sonnet rubber-duck |
| v2 | Design from JSON fixture summaries; never read MATLAB source | GPT-5.4 cross-model |
| v3 | Design from MATLAB source (correct methodology) but rewrite scope was incomplete — touched §1.1/§2.4/§3.6 contract/§6 but not §3.1/§3.5/§3.6 residual code/§5.4 chassis claims | **Opus 4.6 + GPT-5.5 convergent critique** |

The pattern v4 must avoid: **incomplete rewrite propagation**. Every decision in §1.1 or §2.4 or §6 has section-level downstream consequences in §3, §5, §6.2. v4 needs a section-by-section propagation checklist as part of its self-critique.

The pattern v4 must adopt (from v3, kept): **bottom-up construction from `_flat.mat` evidence + a Python extractor that emits machine-readable JSON**. The methodology was right. The execution discipline was off.

# OpenCell v1.x scope

**Status**: draft, 2026-05-23. To be ratified after Phase E.2 publishes the first 28-KP scorecard.

This document defines what belongs in the **v1.x release bucket** (versus v1.0, v2+, v3+, or OpenCell-specific tooling). It exists so Phase E.3's `DEFER-TO-V1.1` dispositions land in a coherent roadmap rather than an ad-hoc todo pile.

## Bucket framing (from cross-cutting decision `v1-trajectory-buckets`)

| Bucket | Meaning | Examples |
|---|---|---|
| **v1.0** | Karr 2012 replication — structure, integration, baseline phenotype match | M4 chassis_v6, Phase E.1/E.2/E.3 |
| **v1.x** | **Karr-known-incomplete fixes**: things Karr's 2012 paper or supplement acknowledges as scoped-out, deferred, or known approximations — and our port's own Karr-light scopings that should be lifted | (this document) |
| **v2+** | Biology beyond Karr 2012 (e.g., signaling cascades absent from the original model, regulatory networks Karr didn't include) | not in scope here |
| **v3+** | Validation and organism-scaling (e.g., wet-lab comparison campaigns, port to *E. coli*) | not in scope here |
| **Tooling** | OpenCell-specific infrastructure (Vivarium adapters, fixture caching, dashboards) | parallel track |

**v1.x is NOT a junk drawer.** Every v1.x ticket must satisfy three criteria (defined below).

## v1.x acceptance criteria (ticket admission)

A ticket belongs in v1.x if and only if all three hold:

1. **Karr-traceable**: cites a specific Karr 2012 source (paper section, supplement, or `.m` file at `data/m1_sources/WholeCell/.../<Process>.m`) that establishes the desired behavior. "Karr says X; we currently do Y."
2. **Concrete acceptance criterion**: states a measurable target (a KP band, a test that should pass, a warning that should disappear). Not "improve fidelity"; rather "raise tRNAAminoacylation charged-tRNA steady-state from 70% to within Karr's published 67±5% band."
3. **Bounded scope**: implementable in a single Codex turn (≤150k tokens, ≤8 checkpoints, ≤2 days wall-clock at observed throughput). Larger work re-buckets to v2+ or breaks into v1.x sub-tickets.

If any criterion fails, the item is **rejected from v1.x** and either (a) re-bucketed, (b) closed as out-of-scope, or (c) downgraded to a tooling/cleanup todo.

### C. Karr-light → Karr-full upgrades (medium confidence)

Several Phase B/C processes shipped under explicit "Karr-light" scoping (per `SESSION_CONTEXT.md` §74-79: per-tick rates matching Karr's traces but bulk state changes rather than per-nucleotide mechanics). Each such deferral should have a "v2 scope" note in its module docstring. v1.x audits these notes and lifts the ones whose lifted form is needed to pass an E.2 KP.

Candidates to audit (per chassis_v6 inventory, exact list TBD):

**Selection rule**: a Karr-light scoping is lifted only if (a) an E.2 KP fails because of it, AND (b) lifting is bounded scope per criterion 3 above.

E.3's `BLOCK-RELEASE` disposition feeds this category and gates v1.0 release entirely.

## Out of scope for v1.x

The following are explicitly **NOT** v1.x; raising them as v1.x tickets is rejected:

- Adding biology Karr 2012 doesn't model (signal cascades, novel regulatory networks) → v2+
- Porting to other organisms (*E. coli*, *S. cerevisiae*) → v3+
- Wet-lab validation campaigns → v3+
- New Vivarium features unrelated to chassis fidelity → tooling track or upstream
- Performance optimization beyond what a KP requires → tooling track
- UI / dashboard / visualization work → tooling track

## Storage and tracking

E.3 will INSERT v1.x tickets into `opencell_tasks.db`. Current schema (`todos` table) lacks a `milestone` column; E.3's first commit must add one via:

```sql
ALTER TABLE todos ADD COLUMN milestone TEXT;
```

Convention:
- `milestone = 'v1.0'` — must ship before v1.0 release (BLOCK-RELEASE class)
- `milestone = 'v1.1'` — first v1.x point release
- `milestone = 'v1.x'` — committed to bucket but not yet assigned to a point release
- `milestone IS NULL` — pre-existing todos; backfill not required

Query pattern for "what's queued for v1.x":
```sql
SELECT id, title FROM todos
WHERE milestone LIKE 'v1.%' AND status = 'pending'
ORDER BY milestone, id;
```

## Release cadence target

- **v1.0**: Phase E gate (G1-G7) passes; per-KP tolerances baked in; release notes cite known v1.x scope.
- **v1.1**: first ratchet release; addresses Section A wiring gaps + 3-5 highest-confidence Section B ratchets + any Section D hotfixes.
- **v1.2-v1.x**: each release ratchets 3-5 more KPs (no big-bang); release notes cite which Karr 2012 source motivated each fix.
- **Cutover to v2+**: declared when remaining v1.x candidates are either (a) judged Karr-incomplete (move to v2+ as "biology Karr didn't model") or (b) too costly per criterion 3 (bounded scope) to lift without restructuring.
